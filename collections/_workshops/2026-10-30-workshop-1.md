## intro

In this workshop, we will be writing code that we can turn into knitted textiles using a Kniterate machine. Like many learning processes, we will need to start small, but where we learn something that can lead on to something bigger we'll try and include some examples. 

We will first be learning  about a language called ["Knitout"](https://textiles-lab.github.io/knitout/knitout.html). This is the foundation and basis of everything we are doing, and it's important to be able to understand and read it (though for reasons that will become clear, after today we are almost never going to write it). Once we are comfortable with what knitout means and does, we will learn about a second language, called ["KnitoutJS"](https://github.com/textiles-lab/knitout-frontend-js) (the "JS" stands for "Javascript") that makes writing it much easier.

## Knitout

<span class="marginnote">
    <img src="{{ '/img/workshop-1/knitout.png' | prepend: site.baseurl }}"/>
    this is what knitout looks like
</span>

[Knitout](https://textiles-lab.github.io/knitout/knitout.html) is a language for representing instructions given to industrial knitting machines. The *cool* thing about knitout is it doesn't matter what machine you're using -- there are ways of translating knitout for our machine (the <a href="https://www.kniterate.com/">Kniterate</a>) but also to other industrial machines like <a href="https://www.shimaseiki.com/">Shima Seiki</a>.

We are using a tool called the **[Patchwork Knitout Editor](https://knit.patchwork.inkandswitch.com/)** (<- click me!) to visualise the knitout code we are writing. It is based on a tool made by Gabrielle Ohlson and Jim McCann at Carnegie Mellon University, called the [knitout visualiser](https://textiles-lab.github.io/knitout-live-visualizer/). We're using the Patchwork tool because it will let us do some extra stuff further down the line. If for whatever reason the patchwork version isn't working for you, the Textiles Lab version will let you do everything you need for today.

### example 1: chain

If you're using the Patchwork editor, select 'knitout example' in the sidebar. We want to delete everything in the file until all that's left is the following code:

```
;!knitout-2
;;Carriers: 1 2 3 4 5 6

in 3
knit + f1 3
```

The first two lines of this file are what's called the 'header' -- they tell our program what version of the knitout language we are using, and what kind of knitting machine this is for (we are using a Kniterate, which has 6 carriers).

<span class="marginnote">
    <img src="{{ '/img/workshop-1/screen-1.png' | prepend: site.baseurl }}" alt="main"/>
    <span class="mainnote">knitout code (left) viewed in the visualiser (right)</span>
</span>

The next line "brings in" carrier number 3. This tells the machine that we want to work with that yarn and brings it up to the needles. The final line here, `knit + f1 3`, is more complex. This one translates as:

> Knit, in the *positive* direction, a stitch on *needle 1* on the *front* bed, using *carrier 3*

Side by side, your page should look like to the right. What we are seeing in the visualiser on the right hand side is the very first stitch, on needle 1.

Right now our first stitch looks like an open loop. We need to add a stitch on the next row to close it. We can do this by adding a second line. As we've knitted our first 'row' in the positive direction (left to right), to add another row to our first stitch we'll need to go in the reverse direction, also on needle 1. Our file now becomes:

<span class="marginnote">
    <img src="{{ '/img/workshop-1/chain-1.png' | prepend: site.baseurl }}"/>
    Adding a second row
</span>


```
;!knitout-2
;;Carriers: 1 2 3 4 5 6

in 3
knit + f1 3
knit - f1 3
```

Now, if we want to make a chain, all we need to do is keep adding stitches.

### example 2: rows

<span class="marginnote">
    <img src="{{ '/img/workshop-1/row-1.png' | prepend: site.baseurl }}"/>
    A first row, with five needles
</span>

What if we wanted to have our piece of knitting be more than one stitch wide? For this, we'll need to start using some more needles. Say we want our sample to be five stitches wide. We'll start in the same way, but this time we'll keep going with our row past needle `f1`. Note that we keep using the carrier 3!

```
;!knitout-2
;;Carriers: 1 2 3 4 5 6

in 3
knit + f1 3
knit + f2 3
knit + f3 3
knit + f4 3
knit + f5 3
```

To get our second row, we'll want to use the same principle as before. Our carriage has gone to the right hand side of the knit. If we simply add a second row in the positive direction, we'll get the issue you can see on the right. This happens when yarn is brought across the bed (as a 'float') to a new location: in this instance, the left hand side of a row, even though the yarn has finished on the right.

<span class="marginnote">
    <img src="{{ '/img/workshop-1/row-float.png' | prepend: site.baseurl }}"/>
        the stitches on the second row are in the wrong direction
</span>

```
...
knit + f4 3
knit + f5 3

knit + f1 3
knit + f2 3
knit + f3 3
knit + f4 3
knit + f5 3
```

We also don't want to do the following: this actually is even worse than before! even though our carriage direction is right, we're now knitting our needles in the wrong order.

<span class="marginnote">
    <img src="{{ '/img/workshop-1/row-order.png' | prepend: site.baseurl }}"/>
    the stitches on the second row are in the right direction but the wrong order
</span>

```
...
knit + f4 3
knit + f5 3

knit - f1 3
knit - f2 3
knit - f3 3
knit - f4 3
knit - f5 3
```

Instead, we need to knit from right to left, *both* by telling the carriage to move in that direction, *and* by knitting the needles in the right order.  That means starting from the higher-number needles!

<span class="marginnote">
    <img src="{{ '/img/workshop-1/row-2.png' | prepend: site.baseurl }}"/>
    the second row working correctly
</span>

```
...
knit + f4 3
knit + f5 3

knit - f5 3
knit - f4 3
knit - f3 3
knit - f2 3
knit - f1 3
```

### example 3: stripes

If you've ever knitted with a domestic or even an industrial machine, you'll know that all you need to do to get a stripe is to change the yarn your carriage is using. We're going to do the same thing here. Unlike a domestic machine, to change yarns, we are going to select a different carrier -- up till now we've only been using carrier number 3.

Carriers 1 and 6 are reserved for the waste section (more on that in Workshop 2), so for now we can pick 2, 4, or 5. Let's go with 4.

If we take our rows example from before, and finish with carrier 3 on the left hand side (this is good practice if you're going to leave a carrier more than a few rows), then we can continue as follows:

    we got a stripe!
</span>

```
...
knit - f2 3
knit - f1 3

knit + f1 4
knit + f2 4
knit + f3 4
knit + f4 4
knit + f5 4
```

### example 5: transfers
The last thing we're going to try in pure knitout (before we explore some ways to make our lives easier) are transfers. Transfers are a way of passing stitches *between beds* -- in practice, a sample rarely starts on the back bed, and normally will use both. The way we "bring in" those needles is by transferring them.

So far we've just used the "knit" command in knitout. This has been fine, but we've not tried to knit stitches with a front needle on one row, and a back needle on the next. What happens if we try knitting a row on the front, followed by a few rows on the back:

<span class="marginnote">
    <img src="{{ '/img/workshop-1/xfer-1.png' | prepend: site.baseurl }}"/>
    even though we're now knitting on the back bed, the front bed is still holding the loops from the previous row
</span>

```
...
knit - f5 3
knit - f4 3
knit - f3 3
knit - f2 3
knit - f1 3

knit + b1 3
knit + b2 3
knit + b3 3
knit + b4 3
knit + b5 3
...
```

It takes a few rows to see the problem -- our front stitches are still held on the needles. After a few more rows, our sample is going to start to be under serious stress!

To get around this, we are going to use transfer command. Consider the following:

```
xfer f1 b1
```

This means:

> Transfer the stitch on *front needle 1* to *back needle 1*

Note a few things:
1. we didn't need to specify the direction
2. we didn't need to specify a carrier
3. the needle numbers match

Points 1. and 2. are for the same reason -- transfers don't involve any additional knitting, as they're just taking a loop and passing it between needles. They don't affect the position of the carriers, or use any yarn.

Point 3. is normally, but not always the case. Ordinarily, needle `f1` and `b1` are facing one another, so the machine can easily transfer the loop from one to the other. If you wanted to transfer from `f1` to, say, `f2`, you'd need to do something called *racking*, where you move the front bed. We won't get into that now, but it's definitely possible.

This is where we can do nice things like transitions. Perhaps we want to knit a couple of rows on the front bed, then transfer our stitches, and then knit some rows on the back bed. Let's try that.

<span class="marginnote">
    <img src="{{ '/img/workshop-1/xfer-2.png' | prepend: site.baseurl }}"/>
    transferring from front to back
</span>

```
...
knit + f1 3
knit + f2 3
knit + f3 3
knit + f4 3
knit + f5 3

knit - f5 3
knit - f4 3
knit - f3 3
knit - f2 3
knit - f1 3

xfer f1 b1
xfer f2 b2
xfer f3 b3
xfer f4 b4
xfer f5 b5

knit + b1 3
knit + b2 3
...
```

This is all very well and good. It will work on the machine! It's valid knitout code! But it's not very fun to write, and it's very hard to make changes. Even if we write out the first two rows and just copy and paste, we're going to have a bad time.

This is where KnitoutJS comes in. KnitoutJS was written by the same people that made Knitout, to make it easier to write! They've since made some other tools, but we liked KnitoutJS and wanted to use it more. What it lets us do is write the same commands we were already writing using a programming language called Javascript. The cool thing about Javascript is that it's a full programming language by itself: this means that we can start using other computer things (data! 3d objects! images!) to make knit.

First of all, though, we need to know the basics.

### example 6: rows revisited

Let's go back to our example with the rows. The first thing we can do is try and simplify our code. In knitout, 2 rows of 5 needles looks like this:

```
knit + f1 3
knit + f2 3
knit + f3 3
knit + f4 3
knit + f5 3

knit - f5 3
knit - f4 3
knit - f3 3
knit - f2 3
knit - f1 3
```
To get started with rewriting our code in KnitoutJS, we're going to go back to the sidebar and select the file "knitoutJS example" in the sidebar on the left hand side. This is the editor that we're now going to use. 

The leftmost file is the KnitoutJS file we'll be editing. The *middle* file, you might recognise as knitout. We don't need to look at it, and we can't edit this one: it's *generated* automatically by the KnitoutJS we are writing!

Our very first file in KnitoutJS is going to look like this (paste this into the file to the left of the editor, indicated by the red arrow in the image below):

```
const knitout = require('knitout');
let k = new knitout.Writer({carriers:["1", "2", "3", "4", "5", "6"]});

k.knit("+", "f1", "3")
```

<figure>
    <img src="{{ '/img/workshop-1/knitoutjs-example.png' | prepend: site.baseurl }}"/>
    <span class="mainnote">looking at knitoutjs in the editor</span>
</figure>

Just like before, the first two lines are a sort of 'header'. We also have done something interesting where we make a thing called "k". "k" is going to hold all of our knitout information -- we don't need to worry about it too much for now though.

When we run this code, this should generate the same knitout file that we made back in example 1. If we want to rewrite our 5-stitch row example in KnitoutJS, we can do this using the following:

```
k.knit("+", "f1", "3")
k.knit("+", "f2", "3")
k.knit("+", "f3", "3")
k.knit("+", "f4", "3")
k.knit("+", "f5", "3")

k.knit("-", "f5", "3")
k.knit("-", "f4", "3")
k.knit("-", "f3", "3")
k.knit("-", "f2", "3")
k.knit("-", "f1", "3")
```

So far, not very exciting (we've even used more words!). But because we're in Javascript, instead of using all these lines, we can try using something called a [*for loop*](https://www.w3schools.com/js/js_loop_for.asp). We're going to use the letter `n` to stand in for 'needle', but we could use anything we liked!

```
...

for (let n=1; n<=5; n++) {
    k.knit("+", "f"+n, "3")
}

for (let n=5; n>=1; n--) {
    k.knit("-", "f"+n, "3")
}
```

Now, this *still* hasn't saved us many lines, but the cool thing here is that now we use the same number of lines to knit a sample 5 stitches wide as we do 20.

### example 2: *more* loop

This is cool, but we are still adding a new one of these for loops every time we want to knit a row. What if we wanted to knit 10 rows? Well -- we could try doing the following:

<span class="marginnote">
    <img src="{{ '/img/workshop-1/more-loop-1.png' | prepend: site.baseurl }}"/>
    <i>how</i> many rows?
</span>

```
for(let row=1; row<=10; row++){
    for (let n=1; n<=20; n++) {
        k.knit("+", "f"+n, "3")
    }

    for (let n=20; n>=1; n--) {
        k.knit("-", "f"+n, "3")
    }
}
```
Now we're getting somewhere! 10 rows and 20 stitches makes... 200 rows of Knitout! But we've done it in just 5 lines of KnitoutJS, give or take.

Another way to neaten up our row numbers is to use *conditional logic*. This lets us test to see if something is the case, then change what we do based on a condition.

```
...
for(let row=1; row<=10; row++){
  // does the row number divide by 2
  if(row%2 == 0) { 
    for (let n=1; n<=20; n++) {
      k.knit("+", "f"+n, "3")
    }
  }

  else{
    for (let n=20; n>=1; n--) {
      k.knit("-", "f"+n, "3")
    }
  }
}
```

### example 8: rib

We can also use conditional logic *inside* the for loops that are making the rows, to decide whether stitches should be knit on the front or back bed. Try this out:

<span class="marginnote">
    <img src="{{ '/img/workshop-1/rib-1.png' | prepend: site.baseurl }}"/>
    a rib made using if statements
</span>

```
...
for(let row=1; row<=10; row++){
    if(row%2 == 0) { // does the row number divide by 2
        for (let n=1; n<=20; n++) {
            if(n%2 == 0) k.knit("+", "f"+n, "3")
            else k.knit("+", "b"+n, "3")
        }
    }

    else{
        for (let n=20; n>=1; n--) {
            if(n%2 == 0) k.knit("-", "f"+n, "3")
            else k.knit("-", "b"+n, "3")
        }
    }
}
```

The next thing we want to try and do is recreate our transfer code. In KnitoutJS, the code for a transfer is `k.xfer(fn, bn)`. If we want to knit a row on the front, followed by a row on the back, we can do the following:

<span class="marginnote">
    <img src="{{ '/img/workshop-1/rib-3.png' | prepend: site.baseurl }}"/>
    using for loops to make transfers from front to back
</span>

```
...
for (let n=1; n<=20; n++) {
  k.knit("+", "f"+n, "3")
}

for (let n=1; n<=20; n++) {
  k.xfer("f"+n, "b"+n,)
}

for (let n=20; n>=1; n--) {
  k.knit("-", "b"+n, "3")
}
```
